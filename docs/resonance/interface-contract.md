# 共鸣界面与对局接口

本文件规定规则三的体验流和验收条件，不是完成回执。当前规则以设计、共享配置及服务器状态为准。规则一、二只用于既有存档兼容；旧设计可通过 Git 查询。

## 原生继承

整体接入上游 Git 1db8e51023ae6abaec9370beb81a513d5c4d0b01 的 MatchScreen、Match/PlayerState、WebSocket、Battle Runner 和 store/actions。标题、难度、必要的关卡介绍、备战、战斗和结果沿用原生屏幕及组件，保留三维场地、Spine、四朝向、范围、敌情、机关、召唤物和领袖。禁止退回简化战場或 DOM fallback。

使用 public/js/resonance/native-match-screen.js 的模式适配及 public/css/resonance-native/ 原生样式。底部工具、准备按钮及部署人数沿用原生位置；共鸣只修改卡池、费用、星级、人口、人数型盟约、经济和装备必须的内容，不能以旧自制备战屏继续修补。

云顶的信息关系参考 Riot [商店界面说明](https://teamfighttactics.leagueoflegends.com/en-gb/news/game-updates/tft-interface-update/)、[单位和羁绊详情](https://teamfighttactics.leagueoflegends.com/en-au/news/game-updates/teamfight-tactics-patch-13-12-notes/)、[组件配方交互](https://teamfighttactics.leagueoflegends.com/en-us/news/game-updates/teamfight-tactics-patch-10-16-notes/)及[装备库存和库存合成](https://teamfighttactics.leagueoflegends.com/en-us/news/game-updates/teamfight-tactics-patch-14-23-notes/)。历史资料确定信息关系，不冒充当前赛季像素级截图。

## 界面信息与操作

| 对象 | 默认显示 | 主动展开与操作 |
|---|---|---|
| 标题 | 原生标题、开始、继续、图鉴、全屏打开 | 难度；恢复存档；独立图鉴 |
| 难度与介绍 | 原生难度、必要关卡信息 | 创建新局；不重复选择战场、主盟约或标准开局 |
| 备战 | 原生棋盘、九槽备战、商店、金币、经验、人口、准备按钮、盟约和独立装备库存 | 拖放、四朝向、收回、合法交换和敌情 |
| 商店卡 | 半身像、名字、整张费用底板、盟约、真实技能图标、升星提示 | 单击购买，右键详情，悬停简述；刷新、锁定、购买经验 |
| 干员 | 原生模型、星标、贴地费用轮廓、实际装备 | 场上、备战和商店均可查看详情；战斗时查看实时状态 |
| 干员详情 | 当前实例属性、固定技能和图标、装备、盟约 | 其它星级、天赋、召唤、穿戴、拆卸；不能改选固定技能或模组 |
| 盟约 | 单色游戏图标、不同身份人数、当前档和下一档 | 全部档位及完整实际数值同时展示，突出当前有效条件；自然成员和徽记 |
| 金币收入 | 金币、利息和胜败简记 | 图形利息档位、实际收入分项 |
| 等级经验 | 等级、经验条、人口和价格 | 各费用概率和升级需求 |
| 装备 | 独立物品区、身上最多三件 | 拖到干员；两组件同持有者立即合成；库存拖拽合成和产物预览 |
| 装备详情 | 实际效果、组件、配方和持有者 | 拆卸、回收和合法目标；奖励物品不伪造配方 |
| 策略补给 | 原生选择卡、实际收益和合法目标 | 次级、多选、收起整理后返回未决选择 |
| 黑市军械 | 进度、商品效果和价格 | 兑现、跳过、购买，钱和物品原子提交 |
| 战斗 | 完整实时原生场地、敌人、技能、召唤、装备、暂停和进度 | 暂停、恢复、倍速和详情，不能提前结算再放回放 |
| 回合结算 | 胜败、生命变化、金币和经验分项 | 伤害、治疗、承伤图表、成长和任务；主动打开战报 |
| 最终结果 | 原生结果屏、最终阵容费用/星级/装备和统计 | 单位图表、再开一局、退出 |
| 独立图鉴 | 当前类别与筛选 | 六十人当季池、二十六盟约、装备、配方、策略和经营；原生资料单列 |

一至五费整张商店卡用灰、绿、蓝、紫、金底板和边框；场上以贴地轮廓和星标辨认，不能使用头顶色块或罗马等级。盟约档位用底色和人数文字。

领军精确一人或四人生效，两人、三人不能亮起一人档。普通阶梯达到高档时低档显示已达到，高档为当前生效。所有档位效果同时可见，不要求切换。

## 备战与浮层

棋子容量九，物品独立。保留原生几何时额外展示格不可使用；privateView 明确 handCapacity，备战槽编号持久稳定。移动、交换和重载不能压缩后变成另一位置。交换同时验证两个目的地和人口，失败不改变任何权威数据。

停靠详情、收入和盟约面板按实际商店矩形避让，缩放、商店折叠和手机横屏后重新计算。打开后所有商品、刷新、锁定、经验、准备和部署人数必须可见可点。选择覆盖层可收起但不丢未决选择。

沿用原生拖拽和朝向轮。D 刷新、F 经验、E 出售、W 部署或收回在输入、朝向、战斗及请求处理中不误触。正文可鼠标选择。按用户当前要求不添加复制定位按钮或自制右键定位菜单；右键用于游戏详情和配方，既有详情深链保留。Workshop 全屏链接保留会话和详情地址，打开远端独立页。

## 原生协议与保存

创建后经 /resonance/ws 使用原生 welcome/catalog/room、g.ready、b.start/progress/end/result 和 settle。普通、中段、最终领袖、隐藏领袖和轻松后勤保留各自阶段及真实时钟，不能统一转普通场。

经营走原生 g.resonance 白名单，禁止 fight 绕回同步战斗后播放录像。HTTP 创建和只读状态保留；COMBAT 拒绝所有经营。开战只锁 Spec，真实结束前不扣经营生命、不加回合、不发钱和奖励。battleId 在处理中和完成后去重，只执行一次共鸣结算。

存档保存阶段、场地类型、Spec、真实时间、暂停和持久 UID 映射。断线及进程恢复重建同一场，不重发奖励或改变场地。服务关闭等待写入并传播保存失败。旧局按保存版本读取，受保护存档不改写。正式存档目录：E:/WindowsWorkspace/webworks/apps/stronghold-protocol/runtime/resonance/player-sessions；测试使用独立固定目录。版本用 Git commit，不设摘要闸门。

## 验收

先完整无头机制、自然经营和费用对照，再真浏览器操作全部流程。桌面 1366×768、1440×900 与移动横屏检查命中区域、重叠、模型、技能图标及玩家文案。必要流程未运行、网络错误、页面错误均不能通过。原生 CSS 相同和组件存在不能代替运行画面。完成后本机 13001 经 Workshop 原卡分发，不部署云端。
