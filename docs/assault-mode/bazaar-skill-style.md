# 进击技能：大巴扎风格标准

> 2026-10-24 起，本文件仅保留旧标准的历史记录；当前卡面、原语、配额与验收以 [大巴扎改编设计稿](bazaar-adaptation.md) 为准。

2026-10-20 用户要求：技能要有大巴扎风格，描述也要和大巴扎近似，改好后由用户验收。以下记录当时标准。依据：用户原需求卡（canvas-0470c0a1 / text-c536b659，「卫戍协议：进击」节）、大巴扎官方数据库 `E:/WindowsWorkspace/webworks/apps/stronghold-protocol/data/assault-sources/bazaar/cards_generated.json`（物品文本）与 `skills_generated.json`（技能文本）、官方中文 `translations_zh_cn.json`。

## 改写前的问题（2026-10-20 实测公开规则）

- 172 个战斗形态中 103 个的进击被动只作用于自身，与其他干员没有关系；大巴扎的成型逻辑是物品之间互相触发。
- 首屏文字中位数 324 字、九成在 480 字以内；大巴扎物品文本中位数 2 行、约 88 个英文字符。
- 首屏分成进击机制、自动技能、进击联动、固有天赋、模组多块，夹带结算口径（「同名刷新取较长剩余时间」「整次施法共用一次判定」「每 8 秒最多一层」）。

## 卡面结构（首屏）

照大巴扎物品提示框：

1. 标题：干员名、星级（一至四星对应青铜、白银、黄金、钻石）、类型标签（职业、分支、阵营/盟约，相当于大巴扎的物品类型）。
2. 技力徽记：技能所需技力，相当于大巴扎卡面上的冷却数字。被动形态不显示。
3. 效果行，最多 3 行，每行一个从句、不超过 30 字：
   - 第 1 行是主动：技力满时自动施放的效果，以动词开头。例：「造成 240% 物理伤害（2 名敌人）。」
   - 第 2、3 行是被动、扳机或光环。例：「当你施加寒冷时，为此干员充能 1。」「相邻的术师干员 +10 攻速。」
4. 三星解锁并选择了模组后，追加 1 行，行首是模组名，相当于大巴扎的附魔行。

首屏不放：职责概述（「先锋：开局低费先锋……」）、原作技能和天赋原文、结算口径、内部编号。原作内容留在第二页「属性与原作」。完整的星级数值和必要的限制条件放在可展开的「详细」里。

数值：卡面只写当前星级的数；详细里用「160 » 200 » 240 » 300」写四档，当前档高亮。

## 句式

照大巴扎官方中文句式：

- 主动：「造成 X 物理伤害」「治疗 X」「获得 X 护盾」「加速相邻干员，持续 X 秒」「施加 X 秒寒冷」。
- 扳机：「当[主体][动作]时，[效果]。」触发看施加不看状态转换。主体优先写类型或位置：「当你的先锋干员部署时」「当相邻干员施放技能时」「当敌人获得寒冷时」。
- 光环：「相邻的[职业]干员 +X 攻速。」「你的[阵营]干员获得……」
- 次数限制用大巴扎写法：「每场战斗前 3 次」「每场战斗首次」，不用「每 N 秒最多一层」「同名刷新取较强」。
- 成长：「本场战斗中 +X」「永久 +X」，最多层数写在句末括号里：「（最多 5 层）」。

## 机制要求

- 至少八成的形态有一行和其他干员发生关系：按类型、按位置或按事件。纯自身数值行不能占满首屏。
- 每行都必须真实执行，文字有而机制无不允许；机制改动沿用现有原语（施加状态、攻击、击倒、部署、召唤回收、护盾破裂、受伤等触发；伤害、治疗、增益、加速、充能、降低技力、再部署、费用、成长等效果；按职业、阵营、位置选友军）。
- 原需求「所有干员切换成瞬发技能，没有就把最有特色的技能改成瞬发并在技能名后加（进击）」「技能自然回复、按时触发」「部分原天赋可以保留」继续有效；保留的天赋也要写成上面的句式。
- 白面鸮这类原作光环如果在自然回复体系里会变成永久加速，要改成大巴扎式的有限加速。

## 收藏品（大巴扎技能）

一行，不超过 40 字，句式同上：「当你……时，……」「你的[类型]干员……」「每场战斗开始时，……」「每场战斗前 N 次……」。
