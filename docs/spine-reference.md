# 2D / Spine 统一语义参考层

首轮目标是让不同拓扑的素材能回答同一个“哪部分、哪一点、这一段怎样移动”的问题。现有动画只读；本原型不修复动画，也不生成新动作。

入口：`/dev/spine-reference/index.html`。浏览器使用项目现有 Pixi / Spine 运行时解析 JSON 与二进制 skel。

## 表达与边界

共同语义包含头中心、颈根、胸参考、腰、骨盆参考以及两条肩肘腕、髋膝踝支链，另有掌心、脚底和武器握持/尖端。每个点记录原素材局部绑定、当前世界位置、固定尺度归一化位置和状态。点允许位于骨原点之外，也允许由多个点计算而来；缺失点保留 null 和原因，禁止回落到零点。

L/R 是稳定的素材支链名，不是已核验的人体左右。两份素材艺术家的命名约定不一定一致；正面与背面也不能凭屏幕 X 排序。未来应逐角色校准 anatomicalSide，而不是让读者猜测。

头中心与脚底是人工检查后的局部偏移候选，关节原点仍标记为候选。胸/骨盆是虚拟参考，不能当成真实关节。掌心、脚接触、点级遮挡、掌面和刃面朝向暂未知。绘制顺序能描述前后层，但不能证明某一点被覆盖。史尔特尔的常态和变身有不同骨树；变身形态尚未标定，不能套用常态人体点。

部件按每份素材的槽位规则归属到头、躯干、手臂、腿、武器和饰物，同时保留未映射槽位和当前是否渲染。region 使用实际运行时 updateOffset 生成纹理边框；mesh 使用实际蒙皮后的顶点。纹理边框含透明区，不能当成身体轮廓。

三种输入：2B 正面（27 骨）、史尔特尔正面（162 骨）、史尔特尔背面（103 骨）。适配器是人工/AI 辅助校准的初始映射，尚未证明能全自动识别新素材。

## 连续帧与机器读取

`observe(raw, profile, {animation,time})` 产生公共格式，`queryPose(pose, 'leg.L.knee')` 在不同素材上使用同一语义入口，`motionBetween(a,b,id)` 输出位移/速度而不猜接触或旋转。归一化原点是骨盆，尺度是固定参考高度，不能每帧按包围盒缩放。世界坐标不包含浏览相机变换。

导出动作序列默认等间距 25 个原生动画采样。它适合开始建立参考数据；快速动作/遮挡段还需更密集采样和逐点视觉校准，不把采样数当质量证明。

浏览器和导出 CLI（绝对路径示例，请替换 code/out 为本次实际工作目录）：

```powershell
node tools/spine-reference/capture.mjs --install E:\WindowsWorkspace\webworks\apps\stronghold-protocol --code E:\WindowsWorkspace\webworks\apps\stronghold-protocol --out E:\WindowsWorkspace\webworks\apps\stronghold-protocol\runtime\spine-reference-20261008
```

CLI 检查真实运行时的 region 几何、跨相机不变性、当前手部变体选择、统一语义查询、两段原生动画导出、变身未知。所有文件路径在回执中列出。截图必须人工/模型查看，机械验证不代表解剖位置已全部正确。
