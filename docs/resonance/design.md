# 卫戍协议：共鸣

本文件规定当前重做的体验、规则来源与验收边界。当前实现版本为规则三；规则一、二仅用于读取已有存档。规则数值以共享配置和逐条来源表为准，推演修订必须同步实现、玩家文案和验证。历史版本通过 Git 恢复，不与当前设计并列作为默认规则。

## 原生底座与对局

整体沿用上游 Git `1db8e51023ae6abaec9370beb81a513d5c4d0b01` 的完整 Match 阶段机、PlayerState、WebSocket、Battle Runner、store/actions 和 MatchScreen。使用模式钩子替换经营、卡池、人数型盟约与经济结算，保持原生布阵、朝向、范围、敌人行进、防线、机关、召唤物和领袖表现。干员与关卡的数据输入使用已核验的本机正式目录，不复制运行资源。

战斗由同一份 BattleSpec 在原生 Runner 中实际推进。开战只锁定阵容并开始作战，不提前计算胜负、扣血、增加回合或发放收益。只有实际完成的 BattleResult 可以结算，同一个 battleId 在处理中和完成后都不能重复结算。战斗阶段拒绝招募、部署、合成及任何能够绕回旧同步战斗路径的操作。历史回放只在主动打开战报时进入。

暂停、恢复、断线接管、进程重启后的恢复与退出遵循原生阶段和协议。保存阶段、场地类型、Spec、实际时间、暂停状态和稳定编号映射；恢复领袖战不能变成普通场。结算只执行一次模式经济，不能再叠加工坊的扣血、金币、累计盟约层数与奖励。

标准、困难、轻松与深渊仍使用卫戍的真实关卡。模式节点与原生波次分开映射：普通中段、最终领袖、深渊隐藏领袖和轻松的后勤节点分别有明确路径；不能将所有节点强制走普通 COMBAT，也不能让共鸣的第十四节点误触原版第十四波领袖逻辑。

## 同季原型与完整卡池

人数结构采用云顶 Set 13、补丁 14.23 的固定数据原型。Riot 官方补丁说明确认赛季背景；完整条目来自版本锁定的 CommunityDragon 客户端数据提取，明确标为社区提取，不能把它冒充 Riot 官方完整目录。

正式参考输入：`E:/WindowsWorkspace/webworks/apps/stronghold-protocol/data/resonance-reference/tft-set13-14.23.json`。该输入收齐本季自然棋子、自然羁绊、对应装备及强化；条件 TeamUp 单列，不伪装成自然成员。全文效果表在 [同季参考表](reference/tft-set13-14.23.md)。

当前自然赛季池为六十名不同 charId 干员，一至五费数量分别为十四、十三、十三、十二、八。每个云顶棋子槽位对应一个干员；费用由对应槽位确定，不沿用原作稀有度或工坊等级。每个盟约的门槛、上下界、自然成员数与各费用成员数组都由同一季原型生成。成员在不同盟约之间共享时仍使用同一干员和同一费用。

完整映射、全部人数档位、自然成员及费用分布见 [赛季映射](prototype-season.md) 与同名 JSON；共享可执行配置为 `shared/resonance/prototype-season.js`。这些文件由一个编译入口生成，不能各自手改成互不一致的名单。

用户举例表达“必须有真实基础”，不构成具体人数规格。禁止统一设计二人起效，禁止为迁就旧的六十五人、三十五盟约而修改来源结构。例如家庭从三人起效，研发使用三、四、五、六人档，领军只在一人或四人时生效；领军两人、三人不能错误激活一人档。最高档超过自然成员数时，必须有真实徽记或明确来源的额外计数路径。

玩法盟约使用中性的战斗名称，避免为满足跨盟约结构而伪造干员国籍。国籍、组织等原作身份作为资料显示。自然人数按不同 charId 计数；同身份重复干员、召唤物、返场不增加人数，备战区不计入上阵盟约。转职赋予持有者额外盟约，同名转职不重复计数。

## 盟约与策略

每项效果保留具名来源、补丁、触发、对象、收益、上限、持续与重置条件。源变量的含义不能从模糊关键词猜测。确需将六角距离、法强、护甲、法力、击败玩家等机制适配为卫戍场地、原生属性、技力和关卡事件时，在设计表明确转换，并以实际 Battle 对照校准；界面只显示玩家需要的最终效果。

逐档玩家文案要显示该档真实数值，所有档同时可见并突出当前有效档。不能每档重复整段模板，不能残留未展开变量或旧季同名盟约描述，不能用零事件计数代替“尚未触发/未知”。每一项保留效果都必须有实际消费者，定义、文案、计量器或空壳 hook 均不算实现。

战斗型效果使用原生 Buff、攻击、命中、技能、受伤、治疗、击倒及时间事件；经济型效果由唯一备战或结算钩子消费。临时成装、实验格、可见召唤物、黑市兑现和军械库必须有实际交互或场地表现，不能仅追加泛用属性。需要追求高档的盟约须在本局合法装备与人口条件下可达，不能为凑人数添加假成员。

策略参考本季完整强化表，从中选编有不同决策作用的经营、刷新、经验、装备、战斗、条件任务与转职机制。不能将整季策略缩成同一种徽记奖励。徽记强化的指定干员、组件或成装奖励需要对应到同季干员槽位及已实现装备；明确适配的差异留在设计表，玩家文案显示最终实际收益。缺失名字或效果的来源条目不能进入可选池。

取消战场/主盟约分池，所有开局共用固定赛季名单。当前新季采用标准开局，没有重复的开局选择环节。策略选择、补给、目标选择、经济兑现等全部通过原生阶段和模式选择覆盖层完成，不能出现有 pendingChoices 却无可点击入口的死局。

## 费用、升星与战斗预算

每名干员固定一个技能，保留技能、天赋、攻击形状、对空、控制和召唤身份；详情与技能图标使用实际选中的技能。禁止从原生详情面板更改固定技能或模组，禁止用闪电占位图冒充技能图标。

先按费用和角色职责给定生命、持续贡献及启动预算，再计入技能倍率、覆盖、技力、控制、治疗、屏障、召唤物和团队收益。更改费用必须重新分配整套战力，不能只改商店价格。属性归一只是起点，不能充当平衡结论。

同星、同装备、同等盟约投入的实战对照应显示高费整体预算更高，同时保留治疗、坦克、控制与输出的不同职责。验证输出、治疗、减伤、控制时间和召唤贡献，避免只按普攻伤害排序。跨星级另测；三星低费能够胜过一星高费是正常追星收益，但一星低费不能因为继承了原生高等级属性而普遍压过高费。

完整固定技能的持续输出另做费用适配：号角当前攻击预算乘0.36，新约能天使乘0.65，其余干员不加个人倍率。倍率作用于费用攻击预算，保留固定技能身份、生命、防护与启动结构；这是共鸣PvE校准，不改写竞品原始值。最终对照使用原生 Battle 实际射程、相同靶防护与进攻压力，区分单体、群体和跨星投入，不以群体总伤排序代替职责判断。

需求明确的新约能天使弹药雨、圣聆初雪雪地与三星技能等作为干员自身的技能/天赋实现，不能为保留它们额外插入伪造人数结构的盟约。召唤、雪地、控制与增益在原生战场可见，并能通过详情理解来源。

## 经营与装备

经营保留招募金币、经验、利息、连续胜败、固定份数卡池、三合一升星与备战区容量。十金币一利息、通常最多五利息；四金币购买四经验，付费刷新通常二金币。开场、自动经验、招募概率、升人口需求、池份与补给节奏必须注明来源版本或明确模式适配，并验证真实整局成型窗口；不同版本数值不能混称为本季原值。

商店五格，锁定可保留商品，未买商品占用份数并在离店/刷新后归还。招募、赠送、复制、升星和出售共用账本；一、二、三星占用一、三、九份。备战区通常九格，上阵人数由等级确定；满备战区升星必须有合法结果席位。所有拒绝为事务性拒绝，不丢金币、装备或池份。

装备库存与干员穿戴通过原生拖拽操作。两组件拖到同一持有者后立即在原槽合成，满穿戴槽但可以合法合成时仍可操作；库存中也可拖拽合成并显示产物预览。唯一装备限制作用于同一持有者。出售、合并、拆卸和溢出回仓有完整路径，满仓时拒绝而非丢失。穿戴装备在预备区和实际战场干员身上显示图标。

普通配方、徽记配方与只能奖励获得的物品明确区分。原型中包含的材料但本模式尚无该组件时，不能擅造配方或假装可合成。徽记高档的合法到账时机须进入推演。

## 原生界面与信息层级

分步进入沿用原生标题、难度、必要的关卡介绍和备战流程，不另加相同名单的选择页。完整卡池和参考资料放在独立图鉴入口。战场保持原生三维场地、Spine、镜头、敌方预览、顶部状态栏、商店、准备/开战按钮与剩余部署人数位置；只加模式必须的信息和操作。

| 干员详情 | 固定技能实际图标、星级、实际属性、天赋、穿戴装备、盟约、召唤物及实时战斗状态 |

费用一至五用灰、绿、蓝、紫、金整张商店卡底板，不能仅给名称栏上色。场上品质以贴地轮廓区分，星级独立显示，不用头顶色块或罗马字母。盟约使用既有游戏图标并统一为单色；不同档位用底色区别。

所有浮层按实际商店几何避让，窗口缩放、折叠商店、手机横屏都要重新计算。详情或收入面板打开后，所有商店卡、刷新/经验/锁定、准备与部署人数仍须可见可操作。文字可选中；详情深链可恢复；不额外放复制定位控件。嵌入画布时提供小的全屏打开链接。产品表面不出现内部变量、路由、制作过程或取证说明。

## 玩法说明

在固定赛季卡池中招募干员、调整站位与朝向，组合人数型盟约迎战各轮敌人。相同干员三合一升星，招募费用与星级分别影响成长；技能、攻击范围、治疗、控制与召唤决定其阵容职责。

商店显示五名可招募干员，整张卡的底色区分费用。锁定保留商品，刷新寻找新干员，购买经验提高等级和上阵人口。金币收入包含基础收益、利息与连续胜败奖励；通常每十金币获得一金币利息，最多五金币。打开收入或经验面板可查看图形分项、升级需求及各费用招募概率。

盟约按上阵的不同干员身份计数。盟约详情同时展示全部人数档位、效果及当前生效条件；领军在恰好一人或四人时生效，其他盟约各有自己的门槛。转职徽记赋予持有者额外盟约，可用于追求更高人数档位。

独立装备库存保存组件、成装和消耗品。把组件拖到干员身上，两件匹配组件会在原槽合成；库存中也可拖拽合成并查看产物预览。干员最多携带三件装备，身上显示实际穿戴图标。点击或右键干员、商店卡及装备，可以查看技能、属性、盟约、配方与效果。

策略与补给提供经营或战斗选择。研发锁定本局赞助装备；险境通过微光进入黑市；远征通过实际击倒积累宝箱；并肩通过存活成员推进家族行动；铸军周期开放永久升级。选择可以收起，整理阵容后继续领取。

实时战斗中可以暂停、恢复和查看干员状态。战斗结束后查看胜败、生命变化、金币与经验收益，以及伤害、治疗和承伤图表；最终结果展示完整阵容、星级、装备与统计。退出后可通过继续游戏恢复本局。

操作快捷键：D刷新，F购买经验，E出售当前选中干员，W部署或收回，空格准备或暂停，Esc关闭当前弹窗。拖动干员完成布阵，右键查看详情；所有资料也可从独立图鉴查看。画布中的全屏打开按钮可进入独立游戏页面。

## 验证与交付

先做无头真实 Battle 规则、效果和整局推演，默认不记录事件帧、回放或视频。人数和费用映射与正式参考逐条比较；全部保留机制须有真实触发/属性消费的证据和同队开关对照。真实费用贡献、跨星级、合法徽记成型、卡池守恒及策略决策均须覆盖。

生命周期至少验证实际 NORMAL 从招募/部署到结束、COMBAT期间经济不变、暂停/恢复、重复结果、断线与进程恢复；普通中段、最终领袖、隐藏领袖、轻松后勤、策略/补给和最终结算都走实际流程。禁止 DeadBattle、预制结果或强制胜利冒充实际对局。

内容收口后运行真实浏览器：原生场地、素材、商店详情、拖拽部署、穿戴与两类合成、全部盟约档位、收入图、选择、实时战斗、暂停、重连、结算与最终阵容；桌面和手机横屏检查重叠、点击可达、文案与完整技能图标。最终通过 Workshop 原试玩卡分发，本机服务仍使用正式13001，不部署云端。

开发只使用一个职责簇稀疏工作树与一个固定临时批次，依赖、素材、正式输入和存档通过已核验的绝对路径访问。磁盘审计包含工作树、输入、运行证据、staging、发布实体和实际驻留 Git 增量，总增量不超过2,000,000,000字节。阶段设确定性检查截止时间，卡住时原地纠偏并继续；最终核验后使用原生 Git 收回不再使用的工作树。
